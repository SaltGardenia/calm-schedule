## 1. WakeUp 课程表（xianfei/WakeupSchedule_BUPT，Kotlin，3.621 版）

WakeUp 课程表是国内使用最广的高校课表 App；该分支是其**完整 App 源码**（非反编译），
含北邮专属优化。本次二次开发最重要的参考。**注**：任务提到的 `Matey-ace/wakeup-course-schedule`
在本机克隆时 GitHub 连接失败且检索不到该仓库（可能已删除/私有），故以 BUPT 分支为准。

### 架构要点（吸收进本项目）

| WakeUp 做法 | 本项目对应改进 |
|---|---|
| XML + 代码动态构建 View（`ScheduleUI.kt` 纯代码布局） | Jetpack Compose 声明式重写（`ui/schedule/ScheduleScreen.kt`） |
| CourseBaseBean（课）+ CourseDetailBean（每次上课），周次 = start/end + 单双标记 | 单实体 `CourseEntity`，周次存显式集合压缩 CSV（支持任意组合如 "1,3,5-15"） |
| WebView 注入 JS 收集 iframe HTML → Jsoup 解析（`WebViewLoginFragment.kt:284-294`） | 同方案实现 `WebViewGrabActivity`，增加自动探测（页面含 `kbtable` 等标记自动抓取） |
| 按学校手选解析器（`ImportViewModel.importSchedule` 按 TYPE 分发） | 升级为**四级自动解析链**（强智→正方旧版→列表式→通用网格，取最多产出），未知学校零配置导入 |
| CSV 导入模板（`CSVParser.kt`：课程名称,星期,开始节次,结束节次,教师,教室,周次） | 完整兼容该格式（`TextImportParser.parseCsv`） |
| `.wakeup_schedule` 分享文件 = 5 行 Gson JSON | 导出为单一标准 JSON（`JsonIO`），语义相同但可读性更好 |

## 2. 开源记账 App 的架构调研（moneybook）与同域参考（sleepy）

任务原文要求"研究已有 github 记账 App 的源码"。`AndersOnLin4/moneybook` 与 `lingion/sleepy`
在多轮重试后（GitHub 连接间歇性阻断）成功克隆到 `_refs/`，以下为**通读源码后**的结论
（前版笔记为网络调研结论，已被源码核实/修正）：

### moneybook「记一笔」（Kotlin 1.9 + Compose + Room 2.6.1，minSdk 28，零第三方 SDK）

- **架构**：单模块约 80 个 Kotlin 文件，`data/{db,model,repository,backup}` + `ui.{功能域}`；
  薄 Repository 直通 DAO 返回 Flow，无 UseCase 层、无 DI 框架——与本项目 `AppContainer` 方案一致。
- **实体设计（值得抄）**：金额存"分"（Long）免浮点误差；日期用 `epochDay`；
  外键 RESTRICT + 查询索引齐全；`onCreate` 回调注入种子数据（`data/model/Bill.kt`、`data/db/AppDatabase.kt`）。
- **导入/备份（`data/backup/BackupManager.kt`）**：JSON 全量导出；导入先做**引用完整性校验**
  再 `database.withTransaction { deleteAll(); insertAll() }` 整体原子落库——本项目
  `TimetableRepository.importReplace` 同思路；CSV 导出带 UTF-8 BOM 防中文乱码；文件读写全走 SAF 零权限。
- **UI**：统计图表全部 Canvas 自绘（`ui/stats/PieChart.kt` 约 40 行环形图），零图表库。

### sleepy「轻课表」（Kotlin + Compose + Material You，minSdk 26，GPL-3.0，约 343 个文件）

- **与本 App 同域，验证了本项目路线**：`data/jw/` 有约 **60 个教务解析器**（正方/强智/URP/wisedu/超星等）
  + `JwParserRegistry` 统一注册 + WebView 登录抓取——印证"解析器逐校适配 + 兜底"是业界做法。
- **可借鉴**：`ImportDraftEntity` 把导入预览持久化为 Room 草稿（进程被杀可恢复、重试幂等）；
  `CourseEntity.groupId` 把一门课的多节次分组（整组编辑/删除）；独立 `PeriodTableEntity` 作息表；
  `ksp { arg("room.schemaLocation", ...) }` 导出 schema 便于迁移测试（本项目已采用）。

### 对本项目的影响

- 上述范式正是本项目的实现方式（`AppContainer` 手动 DI、
  `ScheduleViewModel` 用 `flatMapLatest` 把"当前课表"切换映射到课程流）；
- 记账类应用"账本-账目"两级模型与"课表-课程"两级模型同构，多课表切换交互参考了此类应用；
- 导入原子性（withTransaction）与 SAF 零权限读写沿用 moneybook 的做法。

## 3. HFUT-Schedule（Chiu-xaH/HFUT-Schedule）液态玻璃底栏研究

研究文件（浅克隆 `_refs/HFUT-Schedule`，871 个 Kotlin 文件）：

- `app/.../ui/component/button/BottomBar.kt`（`HazeBottomBarV2`：悬浮胶囊底栏入口）
- `app/.../ui/model/NavigationBarItemData.kt:279-800`（自定义 `NavigationBar` 完整实现）
- `app/.../ui/style/special/HazeBlur.kt`（`bottomBarBlur` / `newBottomBarBlur`：haze 渐进模糊）
- `app/.../ui/component/button/LiquidButton.kt:451`（`bottomBarBackDrop`：Kyant backdrop 着色器）

设计要点（本项目 `ui/nav/AppNav.kt` 的 `GlassDock` 据此复现）：

| HFUT 做法 | 参数/细节 | 本项目复现 |
|---|---|---|
| 悬浮胶囊轨道 | `CircleShape`，水平/底部边距 16.25dp，高 69dp | 68dp 高、16dp 边距 |
| 轨道材质 | Surface + haze blur（5~8.75dp，progressive 顶 0→底 1）+ Kyant 着色器折射 | haze 1.1.1，24dp 高斯模糊 + progressive 级联；不引入 Kyant（着色器依赖重） |
| 轨道/透镜透明度 | `surfaceContainerLow.copy(.75f)`、透镜 `.8f` | **更低透明度**：轨道 0.82/0.74、透镜 0.88/0.78（更实、更易读） |
| 透镜指示器 | 独立 Animatable(left, width)，`tween(200, FastOutSlowIn)`；按下 scale 0.96；`indicatorBlur=2dp` 透镜内二次模糊 | 同款双 Animatable + tween(220)；透镜用 6dp haze 重新采样（比轨道更锐利） |
| 拖动吸附 | 按住透镜横拖切换，跨项 `TextHandleMove` 震动，松手回弹落位 | 完整复现（`detectHorizontalDragGestures` + 仅当起点在透镜内才接管） |
| 条目 | 图标+文字，按下 scale 0.89 tween 300 EaseOut，选中 primary 色 | 复现，按下改用弹簧（临界阻尼） |
| 阴影 | `shadowElevation = 16.25dp` | 由 haze + 描边高光表达，减少重阴影 |

结论：HFUT 的「液态感」= 胶囊 + 独立透镜层 + 拖动吸附 + 渐进模糊；本项目曾按 Apple 液态玻璃原则
（更克制的弹簧、更低透明度、双边缘高光）复刻该底栏。**后续根据产品决定移除了底部导航栏**
（导入/设置改为顶栏玻璃按钮），并移除 haze 依赖；弹窗改为自绘液态玻璃卡片。本节保留作为设计研究记录。

## 4. 教务系统接口规格提取（详见《教务系统适配指南》）

研究素材：`openschoolcn/zfn_api`（新版正方 Python 库，单文件 1707 行，逐函数核对）、
`WakeupSchedule_BUPT` 全部解析器、`haoye999/query-grade`（强智移动端 app.do 协议，确认为
另一协议而非网页端）。核心结论已固化到：

- `docs/教务系统适配指南.md`（登录/课表/字段/陷阱清单）
- `importer/zf/ZfNewClient.kt` 等实现的注释（每条规格标注来源）

三个最容易踩的坑（已处理）：
1. 新版正方 `xqm` 学期码是 `学期²×3`（3/12/27），不是 1/2/3；
2. 正方旧版 `xm` 参数要 GB2312 编码、`__VIEWSTATE` 要用课表页的；
3. 强智 `#kbtable` 单元格内多课以 `-----` 分隔、字段靠 `title` 属性定位，且有 4+ 种版式变体。
